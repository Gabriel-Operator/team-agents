# External specialist runtime contracts

Keep coordinator, reviewer, scorer, judge, auditor, memory and authoritative effects in Gabriel. Only a specialist may select a `runtime`. Omission preserves the existing Mastra path.

Portable runtime alternatives are:

| Kind | Reviewed references |
| --- | --- |
| `a2a` | `resourceKey`, `skillId`, `protocolVersion` (`1.0` or `0.3`), `contractRevision`, `authorityProfile` |
| `managed_claude` / `managed_codex` / `openai_hosted` | `resourceKey`, `profileRevision` |
| `gabriel_peer` | `resourceKey`, `playbookResourceKey`, `contractRevision`, `extensionVersion: "1"` |

Never put remote URLs, bearer tokens, provider credentials, confirmations, memory, live task IDs or execution receipts into a portable team. Resolve the stable key in the running actor’s private Persona workspace. Runtime changes require a draft and renewed human team confirmation.

Use `gabriel_list_external_agent_connections` to inspect authorized private bindings and `gabriel_validate_external_agent_connection` with `expectedRevision` to refresh a saved descriptor. These operations cannot grant assignment data release or manufacture human confirmation. The authenticated private connection UI owns separate data-release review. Card/profile drift invalidates that consent.

Remote completion is a candidate. Validate actual output, provenance, source/ontology compatibility and artifact bytes, then await local review/scoring/judging. Standard A2A cards do not prove broker authority, hidden model-step bounds or cost caps. Missing verified controls hold execution. A reviewed `externalExecution: { limitMode: "invocation", acceptUnknownUsage: true }` can allow a finite assignment on a provider whose internal model calls or expense reports are incomplete. It does not waive unsupported USD or credit caps. Never claim a priced estimate or local timeout enforces a remote spending limit.

Persist the outbound message and invocation before dispatch. Recover by observing a saved task handle; never blindly repeat a send whose receipt was lost. A terminal remote revision starts a bounded new assignment. Uncertain effects/cancellation and unreported expense remain held for reconciliation. Cost corrections must not replay work. Count caller charges separately from informational internal expense.

Native Canvas batches admit shared exclusive resources sequentially and await all started independent siblings before releasing the engine lease. Checkpoint accepted sibling outputs before parking external work. A released or expired native lease permits recovery after a crash before the batch checkpoint; a live or malformed lease holds recovery. Persisted human approvals remain pending until answered through their authenticated endpoint. Team-task acceptance alone does not acknowledge native delivery: retain the continuation until the native engine checkpoint succeeds, then let its leased worker acknowledge delivery and schedule provider cleanup.

Before an externally backed Canvas root finalizes, its live engine saves an encrypted terminal receipt and binds its hash to the reviewed team. If finalization succeeds and the native terminal write fails, recovery restores only that pinned result; it does not reopen tools, rerun models or repeat framework commits. Preserve BSON dates and ordinary numeric values, captured actor/workspace ownership, cancellation and current human-review state. Corrupt, missing or mismatched receipts remain held. Private completion payloads, ownership leases and root completion pins must stay out of client responses and portable assets. Delivery is acknowledged only after the terminal native checkpoint is present for a finalized root.

Offline adapters must refuse these bindings when they cannot enforce the Gabriel kernel and reviewed remote profile. Never substitute local native work for a selected external runtime.
New external assignments include the confirmed task `operation`, its `recordOutputs` mappings, and only the member's record references also captured in the run framework. These are portable declarations; collection IDs, actor identities and mutation credentials stay local. Produce the declared structured output for local acceptance and finalization. The originating server owns the mappings and commits accepted results through the existing exact-effect approval and scoped record services; a remote result cannot replace those targets or mappings.

For an explicitly reviewed `act` task, a brokered profile may expose `write_bound_record` with the exact bound List/pipeline resource key and operation `create`, `update` or `delete`. Create accepts only `{data}`; update accepts `{data,recordId}`; delete accepts only `{recordId}`. Use a closed profile parameter schema containing the approved fields. The server validates the bound column contract, captured run/member permissions and observed record identity, prepares canonical concrete effects, and waits for the authenticated human endpoint before dispatch. Public previews cannot write. The handler rejects caller-selected collections, credentials, undeclared fields and tasks whose finalization mappings already cover that target. Accepted-output mappings retain their separate post-judge finalization path. Returned receipts contain effect/record identities, target resource key, operation and commit time without private collection or ownership details.

Record approvals pin the resolved target and semantic column contract. Changed bindings, schemas, accepted versions or intent payloads remain held. Receipt recovery verifies the encrypted authoritative result hash and the exact owned task/intent version; competing continuations may acknowledge an identical committed receipt but never send another mutation. Protected proposals carry server-derived task/member attribution. A same-task artifact revision cannot redispatch completed or uncertain effects; stored output may continue local review without replaying the capability, and unresolved effects block acceptance.

A brokered specialist can inspect a bound target using `inspect_bound_record_contract`, operation `inspect`, and the exact reviewed resource key. Its input schema is a closed empty object. The handler requires a unique member binding and matching run binding, and returns only field keys/types/required flags/allowed values plus that task's approved output mappings and semantic pin. It reads no runtime rows and grants no mutation permission. It refuses public previews, unbound targets, caller-selected collections and oversized or unrepresentable schemas. Use `read_bound_records` separately only when the member has an approved `read` operation.

Implementation status: external contracts, private connection management, A2A wire operations, encrypted invocation/outbox storage, leased observation, candidate-file ingestion, managed controllers, hosted sessions, peer federation and supported native dispatch paths are implemented in the local checkout behind `TEAM_EXTERNAL_AGENTS_ENABLED`; inbound Gabriel federation also requires `TEAM_GABRIEL_FEDERATION_ENABLED`. Missing adapters, continuations, provider controls or actor-owned credentials fail closed. Local conformance and Docker tests verify adapter mechanics, not live-provider acceptance, deployed cross-instance routing, final invoices or domain quality. Keep external execution opt-in and treat each profile as runnable only after its live capability and account-binding checks pass.

Hosted profiles use the public Agents API contract. `estimatedUsd` is a disclosed planning assumption; it is not an enforced spend limit. The API does not expose a complete session spend cap. Managed profiles use actor-owned provider/model references, a reviewed immutable controller release and a scoped model relay; no application/provider key enters the agent workspace. Real provider and restart tests remain required before declaring a profile ready.


For receiving Gabriel playbooks, set each permitted member’s `delegatedInputTypes` to the exact accepted artifact types it may consume, for example `["video", "edit_decision_list"]`. This is a portable definition change and requires renewed human confirmation. An omitted or empty list grants no access. The receiving worker refuses initial dispatch when no specialist covers an incoming type. Coordination, review and verification members need their own explicit input type selections where they inspect the original evidence.

Incoming file releases must belong to the signed origin invocation and accepted artifact manifest. The receiving worker imports actual bytes into private storage before native launch, checks MIME/size/SHA-256, and checkpoints the immutable inputs. Managed or hosted descendants receive only the input types approved for their member, plus their accepted local dependencies. Native members use `read_delegated_input_artifact`; managed/hosted broker profiles can review the same tool with target `delegated.inputs` and operation `read`. Tool reads retain the producing semantic snapshot and create authoritative lineage events.

Members may use the server-owned `read_bound_data_feed` broker tool when their reviewed framework bindings pin that feed's resource key and revision. Use operation `read`, the exact resource key as the target, and a closed input schema containing only the feed's declared `inputs`. The handler rejects write feeds, caller-selected revisions, locale overrides, credentials and unbound feeds; it runs through the existing Data Feed authority, credential/grant, freshness, ontology and provenance checks. Locale comes from the run's pinned ontology selection. The specialist receives bounded validated observations, never source credentials. Feed access does not authorize List writes; use a separately reviewed record binding and its exact-effect approval flow for mutations.

Only files explicitly named by the accepted final assembly are exported. The receiving signed result binds their identities, producing versions, MIME, size and actual hashes. Task-file downloads require the current authenticated receiving client and workspace; the origin refuses substituted endpoints and hashes before accepting the candidate. Signed complete execution counts reconcile unused descendant task/model allowances atomically. Partial counts retain their conservative reservations. Provider invoices and complete cost settlement still require separate accounting proof.
